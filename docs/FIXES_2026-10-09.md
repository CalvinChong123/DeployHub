# DeployHub repair validation — 9 October 2026

The four findings in the initial review are addressed. No schema migration or dependency change is required.

## Behavior

- **Partial failure:** A failed deployment with updated code exposes **Prepare recovery preview**. The new immutable candidate pins a source deployment, current configuration and the same target SHA. Fresh preflight requires clean HEAD and fetched origin at that target. All selected pipeline steps rerun from the beginning, with no Git merge. Review, expiry, grants, MFA, fresh independent protected-environment approval and execution ownership remain enforced. Unknown state still requires administrator reconciliation.
- **Missing approvals:** Pending unexpired approvals are queried before pagination. Activity search and state filters run over the full authorized history, including literal search characters. Activity and environment history provide older pages; environment pagination preserves its selected tab.
- **Duplicate names:** Environment-name validation is scoped to the project, excludes the current row on edits and returns a form error. Project row locks serialize creation/rename checks. Names can be reused across different projects.
- **Server changes:** The form identifies existing viewers missing the new server assignment. The backend rejects the update unless the administrator explicitly confirms transfer. Server assignments and configuration commit together; environment rights are preserved, viewers remain unable to deploy/approve, and transferred IDs are audited. Permission updates also lock the environment so concurrent changes use the current server.
- **Form display:** Checkbox labels and controls are excluded from text-field layout rules; checkbox dimensions and native selected appearance are explicit. Production, pipeline and access choices are visibly selectable.
- **Formatting:** The two reported PHP test formatting failures are corrected.

## Agent rules

`AGENTS.md` routes agents to `.agents/rules/`. Two concise global rules cover implementation/verification and language/documentation. Three conditional rules protect deployment execution, access/credentials and Inertia response/live-state contracts. Workstation runtime preferences are captured separately in ignored local rules and discover compatible Laragon PHP rather than fix an executable version.

The [bootstrap report](../.agents/logs/BOOTSTRAP_REPORT.md) records the inventory, recoverability and the suitability assessment of the user's Laravel rule-architect skill. That skill is suitable for DeployHub's rule work; it was not modified.

## Limits

Recovery deliberately reruns the configured pipeline; it does not provide arbitrary step resume or rollback. Advancing origin requires a normal new deployment review. Real SSH/cPanel transport, mail, backup restoration and operational production readiness remain unverified.
